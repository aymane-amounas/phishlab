# Privacy

PhishLab handles email that can be genuinely sensitive. Suspicious messages often carry
real victim information, so privacy is a design constraint here, not a setting.

## Defaults

Analysis is offline: the static path makes zero outbound network calls. There is no
telemetry and nothing is phoned home. No third-party APIs are contacted, so no VirusTotal,
urlscan, or reputation services. The UI loads no remote images, fonts, scripts, or CSS,
and a strict Content-Security-Policy enforces that. URLs are never visited automatically
and attachments are never executed.

## Data handling

Raw artifacts are hashed (SHA-256) and stored locally in SQLite. The original evidence is
kept separate from anything the analyst adds (notes, disposition, rationale), so the two
never blur together. Reports defang all URLs and offer an email-address redaction option,
which is on by default for exports. Logging is kept safe: raw bodies, credentials, and
full artifacts are not logged.

## Retention and deletion

`PHISHLAB_RETENTION_DAYS` defaults to `0`, which means keep until explicitly deleted.
`CaseStore.purge_older_than(days)` removes cases past the retention window, and individual
cases can be deleted through the API or UI (`DELETE /api/cases/{id}`).

## Optional network lookups

Disabled by default. If it is ever enabled, the operator owns the privacy implications of
resolving and contacting hosts derived from a sample. Even then, PhishLab never transmits
email bodies, attachments, or full artifacts to third parties.

## Synthetic samples only

Every `.eml` in `backend/samples/corpus/` is synthetic, generated by
`samples/generate_corpus.py` using RFC-2606 reserved domains. There are no real addresses,
credentials, or private data in them, and user-supplied `.eml` files are `.gitignore`d.
