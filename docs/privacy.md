# Privacy

PhishLab handles potentially sensitive email data (suspicious messages often contain real
victim information). Privacy is by design.

## Defaults

- **Offline analysis.** Static analysis makes zero outbound network calls.
- **No telemetry.** Nothing is phoned home.
- **No third-party APIs.** No VirusTotal, urlscan, or reputation services are contacted.
- **No remote resource loading.** The UI loads no remote images, fonts, scripts, or CSS;
  a strict Content-Security-Policy enforces this.
- **No automatic URL visits** and **no attachment execution**.

## Data handling

- Raw artifacts are hashed (SHA-256) and stored locally in SQLite.
- Original evidence is kept separate from analyst-added conclusions (notes, disposition,
  rationale).
- Reports **defang** all URLs and offer an email-address **redaction** option (on by
  default) for exports.
- Logs are kept safe: raw bodies, credentials, and full artifacts are not logged.

## Retention and deletion

- `PHISHLAB_RETENTION_DAYS` (default `0` = keep until explicitly deleted).
- `CaseStore.purge_older_than(days)` removes cases past the retention window.
- Individual cases can be deleted via the API/UI (`DELETE /api/cases/{id}`).

## Optional network lookups

Disabled by default. If ever enabled, the operator is responsible for the privacy
implications of resolving/contacting hosts derived from a sample. PhishLab never
transmits email bodies, attachments, or full artifacts to third parties.

## Synthetic samples only

Every `.eml` in `backend/samples/corpus/` is synthetic (generated by
`samples/generate_corpus.py`) using RFC-2606 reserved domains. No real addresses,
credentials, or private data are included, and user-supplied `.eml` files are
`.gitignore`d.
